# screenwriting-skills 轻量集成

本文件将 screenwriting-skills 的六个核心模块适配到短视频制作，提供随 video-workflow 安装即可使用的方法。它是精简适配，不是上游整套技能的副本；来源和适配范围见 [SOURCE](../third_party/screenwriting-skills/SOURCE.md)。用户无需安装另一套项目系统。

## 何时进入和怎样落地

video-workflow 负责推进、文件和 TapNow 交付，本文件负责创作判断。写新剧本、改剧情/对白、设计分镜衔接时读取；纯改文件名、导出 Word、核对链接不启动编剧分析。默认取当前问题最相关的 1—2 个模块；必要时增加，不能把六项变成每轮全部填满的工作单。

| 当前请求 | 默认取用 | 完成标准和落点 |
| --- | --- | --- |
| 只有想法，要写短片 | 前提与主题、结构与节奏 | 确定表达和可见行动，直接形成剧本；不先交一堆研究表 |
| 现成剧本太僵硬/行为没理由 | 人物与动机、对白与潜台词 | 找到具体行为/句子的问题，改受影响段落 |
| 对白生硬，其他不动 | 对白与潜台词 | 改台词及必要反应，保持已定剧情；仅确实缺动机才补读人物模块 |
| 产品特写突兀，切镜断裂 | 场景与衔接、结构与节奏 | 补因果、声画或视线接点，更新受影响分镜与视频起止状态 |
| 角色造型改了 | 人物与动机中与表演有关部分 | 先同步资产与关联镜；外貌变化不自动推翻故事或角色关系 |
| 参考故事/素材要改编 | 改编与表达，按需加结构 | 保留要表达的核心，改成可拍行为，不复制参考作品对白 |
| 纯产品/氛围、无对白 | 场景与衔接 | 用观察顺序、细节或状态变化组织，不强加反派、成长弧或旁白 |
| 剧情已定，准备 TapNow | 场景与衔接；有新台词才加对白 | 把创作意图落实为单一瞬间、视频动作及发言窗口，不重新开发故事 |

读稿时先指出具体段落/镜号、可观察的问题及影响，再实施已授权的改动。分析在当前回复简述，结果写回已有对应文档；用户只要审查时不擅自改稿。已批准的方向直接执行，不因接入编剧方法再问一次。

不建立 story-bible、人物研究册、节拍卡、诊断台账、独立音色总册或新的项目目录。现有剧本和当前反馈已能保存决定时，不复制另一份项目状态。内部判断不成为用户必填字段，不为接入本模块新增内容检查门槛。

## 前提与主题

对应 sw-premise-theme 的前提、主控思想、一句话故事与戏核方法。

- 先抓住这支片中谁想做什么、遇到什么具体条件、最终采取什么行动。把表达目标落到能拍出来的选择，不停在“爱”“温暖”“成长”这样的概念上。
- 从结尾动作回看：观众理解了什么变化，前面哪件事让这个变化可信？需要补因果时改行为和情境，避免让角色直接宣读主题。
- 用删减检验核心：拿掉某个动作，片子表达是否仍完全相同？用来辨别内容主次，不要求删去所有氛围和停顿。产品片可以是观察或体验，不必伪造人物冲突。

落点：剧本的一句话故事、关键动作或结尾；只在真正需要澄清时补一句表达目标，不强制增加“前提/主控思想/戏核”三张表。

## 结构与节奏

对应 sw-story-structure 的事件因果、入戏、转变、结尾及短篇结构方法。

- 先沿现有剧情顺序检查信息、动作和反应：每一段为何接在这里，观众到这里需要知道什么，后段用了哪个已建立的条件。两个不同镜头不等于两次情节推进。
- 目标时长以内，估算实际对白、手部动作、反应与留白，优先压缩重复解释和无作用的往返。开头从需要的事件附近开始，结尾留给动作的余味；不机械规定第几秒必须冲突。
- 检查转变有没有过程：说完一句话就突然和解、产品忽然出现、月亮突然切入，都要从当前人物意图和空间找接点。允许克制、静默和微小变化，不强加反转或大高潮。
- 长片页码、十五节拍、四十张卡、固定幕比例不作为短片必交内容。已定90秒项目按90秒容量处理，不能把长篇方法压成一堆卡片。

落点：剧本段落与时长；进入分镜后同步受影响镜号、时间和台词窗口，不重排无关镜头。

## 人物与动机

对应 sw-character-conflict 的人物背景、当下欲望、行动选择与转变过程。

- 从当前事件辨认每个人此刻想得到、避免或隐瞒什么，以及他对对方的了解。背景只保留会改变本场反应的部分；不用为十几秒片段编一生经历或心理诊断。
- 让动机表现为不同的做法：一个人急着结束通话可能是怕打扰，另一个人找小事继续说可能是想陪伴。不要把这些解释全部变成角色台词。
- 行为突然改变时补一个足够的可见触发或反应；不为了“人物完整”增加新角色、创伤、反派或强烈争吵。必要的小犹豫可以成立，不要求每个人结尾脱胎换骨。

落点：剧本动作、角色表演；需要影响造型或声音时再改人物资产说明，并按现有资产关联规则核查下游。

## 场景与衔接

对应 sw-scene-craft 的场景目的、行动反应、细节/道具作用与相邻场景过渡。

- 每段先决定观众要看到什么行为或关系变化，再选择具体动作与景别。情感可以通过停留、递物、倾听表现；有意义的日常交流不因“没有争吵”被删掉。
- 在切点核对前镜实际结束与后镜第一帧：持物、站坐、视线、开合、余量和光线是否接得上；是同一动作继续、反应、视线所见，还是有明确作用的声音延续。纯空镜可以留白，但须知道为什么此时出现、如何回来。
- 轮廓匹配、运动匹配和运镜范围必须有实际参考支持；未看到图片时只给条件方案，不预设产品有某个圆形部件、房间有另一个机位或两镜已经匹配。条件不成立时用现有空间关系或声音接点，不为了转场要求补一套资产。
- 产品先参与人的需要。已确认的功能可用“人物操作—产品响应—人物继续行动”连接；特写显示本次动作真正改变的东西，不能为凑品牌露出随意打断情绪。镜头时长不是产品性能参数。
- 同一道具反复出现时检查是否承担新作用或延续状态，避免每次都像第一次拿起。外观、数量与所属由选用参考固定，动态状态由剧情决定；环境里已有物件不再加一个副本。

落点：分镜 prompt 的确定瞬间和主要锚点；视频 prompt 的动作与结束状态、相邻衔接、必要独立音效。分屏按原工作流分别生成再合成，不为对称破坏两地空间。

## 对白与潜台词

对应 sw-dialogue 的对白行动、信息控制、人物用语、停顿与重复节拍诊断。

- 判断说话人想让对方产生什么反应，再写符合关系和口吻的短句。把本来可以通过动作看见的信息从解释性台词中减掉，保留真正改变关系或信息的内容。
- 区分角色说出口的内容和不愿直说的愿望，优先用具体小事承载情绪；不把每一句都改成金句。自然寒暄若有陪伴、试探或缓和作用就可保留。
- 看连续几句是否只重复同一请求/拒绝。需要推进时改变行为、信息或反应，不仅换同义词；适当停顿由前一句引发，不能机械塞空白。
- 对话放回角色身份和当时动作试读，核对呼吸、反应与秒数。只有实际试听后才能确认速度与口型；文字估时不记为音频已验收。

落点：先统一剧本对白，再同步本镜视频 prompt 中可见说话的原句和独立纯台词；音色、情绪、语速、发言时机仍与视频同镜交付。口语用法不等于固定音色，不能混成一段朗读文本。

## 改编与表达

对应 sw-format-adaptation 的可见动作表达、改编选择与按目标修改。

- 从参考中识别必须保留的事件、人物关系或表达目标，再决定删减和换成可拍动作的部分；区分用户事实、观察和创作，不伪造参考片看不到/听不到的内容。
- 剧本写能看到、听到和演出的行为。抽象心情通过情境、动作或对白体现；旁白只有项目需要时才写，不自动补旁白说明一切。
- 改动按用户的问题收敛：只修对白时不重构全剧，只补产品动作时先查受影响因果和镜头。改编参考作品以新的表达完成，不照搬其影视对白、书籍摘录或商业素材。
- 行业投稿的 Fountain、Courier、页码规则和禁止镜头术语，不适用于这里面向 TapNow 的制作文档。继续使用独立 Word；专业投稿体例只在用户明确要求时另作适配。

落点：剧本正文或对应制作提示词，不额外交一份改编研究报告。

## 深入阅读与冲突处理

内置方法足以支持基础短视频创作；需要原项目的完整论证或特定方法时，按上表选一个已安装的 sw-*，从当前技能目录列表定位其 SKILL.md，必要时再读该包 reference.md。不要猜固定用户路径、全盘扫描、递归加载整套技能或自动下载。

没有安装完整原包时继续使用本内置适配，不把它报成缺失基础依赖；只有请求确实需要未携带的专项资料时说明具体缺项。系列剧、戏曲或明确风格再按实际可用技能补充，不为了短视频预装它们。

外部技能提供创作方法，video-workflow 保持制作调度和文件约定：不执行 sw-workflow 的独立阶段表和 story-bible 管理，不执行与当前媒介无关的长片卡片、人物研究或全量诊断门槛。不以方法判断替代用户授权，也不把当前用户偏好提升成上游所有项目的规范。

编剧修改完成后只核对实际受影响的“剧本 → 分镜瞬间 → 视频动作与纯台词/时机 → 已有素材连接”。最终交付仍是既有三类 Word 的当前稿；本模块不新增任何项目侧文档。
